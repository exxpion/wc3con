# Развёртывание и тестирование WC3 Connector

## 1. Сервер

На Ubuntu VPS установите Node.js 20 LTS и зависимости:

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl build-essential python3
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs
```

Скопируйте проект на VPS, затем из корня репозитория:

```bash
npm ci
cd server
cp .env.example .env
# Установите уникальный JWT_SECRET в .env
npm run build
npm start
```

Рекомендуется поставить Nginx/Caddy перед Fastify и включить HTTPS/WSS. Внешнему миру откройте только HTTPS-порт reverse proxy. TCP/UDP 6112 на VPS не требуется.

## 2. Сборка Windows-клиента

В корне проекта:

```powershell
npm ci
$env:WC3_SERVER_HTTP_URL = "https://your-domain.example"
$env:WC3_SERVER_WS_URL = "wss://your-domain.example/ws"
cd connector
npm run build
npm run package
```

Если переменные окружения не заданы, используются адреса по умолчанию в `connector/src/main/index.ts`.

## 3. Базовый LAN-тест на двух компьютерах

1. Убедитесь, что на обоих компьютерах используется Warcraft III TFT 1.26.
2. Оба игрока входят в лаунчер под разными аккаунтами.
3. Хост выбирает файл карты `.w3x` или `.w3m` в лаунчере и создаёт комнату.
4. Гость входит в комнату и видит заявленную карту.
5. Хост вручную запускает WC3 и вручную создаёт LAN-игру с той же картой.
6. Коннектор должен обнаружить GAMEINFO; игра должна появиться у гостя в `Multiplayer → Local Area Network`.
7. Гость подключается к игре.
8. Хост закрывает LAN-игру: комната лаунчера должна остаться, а устаревшая игра должна исчезнуть из LAN-списка после таймаута обнаружения.
9. Хост создаёт LAN-игру повторно в той же комнате.

## 4. Тесты reconnect и комнаты

- Обрыв WebSocket одного гостя: комната сохраняет место участника 180 секунд.
- Возврат гостя до истечения 180 секунд: сервер восстанавливает его членство.
- Невозврат гостя: сервер удаляет его из комнаты, закрывает его туннели на стороне хоста; остальные участники остаются в комнате.
- Обрыв WebSocket хоста: комната сохраняется 180 секунд.
- Возврат хоста до истечения 180 секунд: хост восстанавливает управление комнатой и повторно обнаруживает свою LAN-игру.
- Невозврат хоста: сервер закрывает комнату и уведомляет всех подключённых участников.
- Явный выход хоста из комнаты через лаунчер до игры: комната закрывается немедленно.
- Явный выход гостя: его место освобождается немедленно.

**Важно:** при `relay_paused` сервер блокирует передачу W3GS TCP-кадров, а клиенты временно буферизуют ограниченный объём трафика. Это должно остановить синхронизированный игровой поток, но точное поведение видимого фризтайма и продолжения матча нужно подтвердить на двух реальных клиентах WC3 1.26.

## 5. Диагностика

- `/health` должен отвечать `{"status":"ok", ...}`.
- Сервер и клиент должны использовать одну версию WebSocket protocol (`protocolVersion: 1`). Обновляйте сервер и клиенты одновременно.
- В логах клиента ищите `[WS]`, `[UDP]`, `[GAMEINFO]`, `[TUNNEL]`.
- Если GAMEINFO не обнаруживается, проверьте, что WC3 запущен и хост действительно создал игру в LAN.
- Если туннель открывается, но игра не подключается, проверьте фактический TCP-порт из GAMEINFO и состояние локального WC3.
- Не занимайте порт 6112 процессом коннектора: он должен оставаться доступным Warcraft III.

## 6. Не закрытые приёмочные проверки

- Реальный фризтайм и продолжение матча после reconnect.
- Исключение гостя из уже идущего матча после 180 секунд без возвращения.
- Принудительное совпадение ника аккаунта и игрового ника WC3 1.26.
- Извлечение фактической карты из GAMEINFO и предупреждение `warn` при несовпадении.
- Полный end-to-end тест на двух физических ПК с WC3 1.26.
